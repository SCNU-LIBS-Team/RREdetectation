# Multi-Agent 论文撰写工作流

## 1. 工作流目标

将论文项目拆分为五条相互校验的工作链：

1. **文献证据链**：文献盘点、分类、去重、证据提取和引用核验。
2. **实验事实链**：数据、实验条件、算法参数、运行记录和结果整理。
3. **科学论证链**：研究问题、方法、实验、结果和结论之间的闭环。
4. **章节写作链**：按章节生成、修订和整合论文文本。
5. **审查与复现链**：检查逻辑、引用、数字、图表、数据泄漏和可复现性。

工作顺序不是“让一个 Agent 直接写完整篇论文”，而是：

```text
证据盘点
→ 研究问题与主张
→ 方法和实验核验
→ 论证骨架
→ 图表与结果
→ 分章节写作
→ 多视角审查
→ 修订和发布
```

## 2. Agent 角色与职责

### 2.1 Orchestrator：总控 Agent

负责：

- 维护项目状态、任务清单和论文版本；
- 拆分任务并决定依赖关系；
- 为并行 Agent 分配不重叠的写入范围；
- 汇总冲突，不静默选择互相矛盾的材料；
- 管理质量门禁；
- 决定内容何时可以进入正式稿。

总控 Agent 不得自行创造未经验证的事实。

### 2.2 Literature Agent：文献分析 Agent

负责：

- 读取和分类已有 PDF；
- 提取研究对象、样品、方法、指标、结论和局限性；
- 建立文献索引和证据卡片；
- 标记关键页码、图号和表号；
- 为引言、相关工作和讨论提供可核验依据。

只凭标题或摘要无法确认的内容必须标记为待核验。

### 2.3 Citation Verifier：引用核验 Agent

负责：

- 核对作者、题目、年份、期刊和 DOI；
- 检查引用是否真的支持对应论断；
- 检查是否把相关性写成因果性；
- 检查是否把识别、分类和定量任务混为一谈；
- 检查是否超出原文证据强度。

### 2.4 Method Agent：方法整理 Agent

负责根据现有代码整理：

- 光谱预处理；
- 小波寻峰；
- 理论和实验元素梳；
- 谱线匹配与冲突峰处理；
- 温度迭代和温度扫描；
- 多峰拟合；
- 相似度和元素置信度计算；
- 阈值和判据。

如果代码中没有明确参数，不得凭经验自行补全，应建立待补充清单。

### 2.5 Data/Experiment Agent：数据与实验 Agent

负责：

- 区分原始数据、外部数据、中间数据和最终数据；
- 建立数据字典；
- 核对单位、波长范围、维度、缺失值和异常值；
- 检查按样品或批次划分数据，避免光谱级泄漏；
- 设计和维护实验矩阵；
- 记录每个正式运行的配置、版本、种子和结果。

### 2.6 Argument Agent：论证链 Agent

负责把每个核心结论组织为：

```text
研究问题
→ 方法设计
→ 实验验证
→ 观测结果
→ 解释和限制
→ 结论强度
```

它需要标记：

- `UNSUPPORTED_QUESTION`：研究问题没有对应实验；
- `UNMOTIVATED_EXPERIMENT`：实验没有服务于任何研究问题；
- `OVERCLAIM`：结论强度超过证据范围。

### 2.7 Writing Agent：章节写作 Agent

建议按章节而不是“一次生成全文”进行：

- Introduction Agent：背景、研究缺口和贡献；
- Related Work Agent：按问题或方法分类综述；
- Methods Agent：可复现的方法描述；
- Results Agent：只陈述已核验结果；
- Discussion Agent：解释差异、错误案例和适用边界；
- Conclusion Agent：区分已验证结论和未来工作；
- Abstract Agent：最后根据稳定正文生成摘要。

### 2.8 Review/Reproducibility Agent：审查与复现 Agent

负责：

- 逻辑和结构审查；
- 数字、单位、符号和术语一致性审查；
- 引用真实性审查；
- 重复表达和模板化表达审查；
- 数据泄漏和统计方法审查；
- 在尽量干净的环境中复现主要流程；
- 模拟 LIBS 专家、机器学习审稿人和复现性审稿人。

## 3. 分阶段执行流程

### 阶段 0：项目初始化与范围冻结

由总控 Agent 建立项目章程，明确：

- 论文暂定题目；
- 论文类型；
- 研究任务边界；
- 目标期刊；
- 论文语言；
- 主要研究问题；
- 预期贡献；
- 主要实验和预计图表；
- 不纳入本论文的内容。

**门禁 G0：** 如果识别、分类、定性和定量任务尚未区分，不进入正式写作。

### 阶段 1：现有材料并行盘点

可以并行启动：

```text
Literature Agent
Method Agent
Data/Experiment Agent
Code Auditor
Existing Results Agent
```

输出：

- 文件和材料清单；
- 文献分类和优先级；
- 代码模块图；
- 数据资产清单；
- 已有结果清单；
- 缺失材料和风险清单。

**门禁 G1：** 所有关键材料都有路径、来源和当前状态。

### 阶段 2：建立文献证据和主张登记

建立两个核心对象：

1. 文献证据卡片；
2. 论文主张登记表。

每个主张应尽量关联：

```text
Claim ID
→ 文献证据或实验事实
→ 图表/统计结果
→ 数据版本
→ 代码版本或 run_id
```

**门禁 G2：** 引言中的核心判断和方法选择都有可核验来源或明确标记为本文设计。

### 阶段 3：整理方法并建立最小可运行流程

目标不是马上得到最佳结果，而是先让以下链路清晰、可运行、可记录：

```text
输入光谱
→ 预处理
→ 寻峰
→ 谱线匹配
→ 元素梳构建
→ 温度估计
→ 多峰拟合
→ 相似度计算
→ 元素置信度输出
```

每个步骤必须说明：

- 输入；
- 输出；
- 参数；
- 代码位置；
- 失败条件；
- 验证方法。

**门禁 G3：** 论文方法描述与实际代码流程没有关键矛盾。

### 阶段 4：冻结实验协议

正式实验前固定：

- 数据版本；
- 数据划分；
- 预处理方案；
- 对照方法；
- 主要指标；
- 随机种子策略；
- 重复次数；
- 异常值处理规则；
- 统计分析方法。

实验变更必须记录：

```text
变更内容：
变更原因：
影响实验：
是否改变主要结论：
批准人/Agent：
日期：
```

**门禁 G4：** 主实验、探索实验、调参实验和失败实验已经区分。

### 阶段 5：正式实验和结果生成

采用实验矩阵，而不是零散地运行脚本。

推荐记录：

```text
experiment_id
purpose
data_version
preprocessing
baseline_or_model
configuration
repetitions
metrics
output_paths
status
```

每个运行生成唯一 `run_id`，禁止覆盖旧结果。

**门禁 G5：** 主要结果可以由数据、配置、代码版本和运行记录重新生成。

### 阶段 6：论证骨架和分章节写作

推荐写作顺序：

```text
Methods
→ Results
→ Discussion
→ Introduction/Related Work
→ Conclusion
→ Abstract/Title
```

写作 Agent 只能使用：

- 已核验的文献证据；
- 已确认的实验事实；
- 已登记的研究主张；
- 已批准的方法说明。

摘要和结论最后撰写，避免引入正文中不存在的信息。

### 阶段 7：多轮审查与修订

每个主要章节完成后，不等到全文结束才审查。

至少执行：

1. 引用核验；
2. 事实和数字核验；
3. 逻辑闭环检查；
4. 重复和表达检查；
5. LIBS 专家审查；
6. 机器学习方法审查；
7. 可复现性审查。

所有意见分为：

- 必须修复；
- 建议修复；
- 可以在回复信中解释；
- 不采纳及理由。

### 阶段 8：投稿前发布检查

投稿版本至少应满足：

- 主要图表可以重新生成；
- 主要表格可以重新生成；
- 每个核心结论都有 Claim ID；
- 数据划分不存在明显泄漏；
- 关键参数和评价指标完整；
- 代码版本和数据版本可追溯；
- 主要 Reviewer 问题已有处理记录；
- 局限性和失败案例没有被刻意隐藏。

## 4. 标准任务交接格式

每个 Agent 完成任务时，使用以下结构：

```markdown
# Task Handoff

## Task ID
TASK-0001

## Agent

## Objective

## Inputs

## Constraints

## Work Done

## Outputs

## Evidence

## Risks

## Open Questions

## Recommended Next Agent

## Status
Draft / Reviewed / Accepted / Blocked
```

如果使用结构化数据，建议采用：

```yaml
task_id: TASK-0001
agent: ""
status: "completed/partial/blocked"
input_refs: []
outputs: []
evidence: []
decisions: []
unresolved_questions: []
warnings: []
next_actions: []
confidence:
  overall: 0.0
  reason: ""
```

## 5. 证据和内容状态

内容状态：

```text
IDEA
→ EVIDENCE_PENDING
→ EVIDENCE_COLLECTED
→ DRAFTED
→ INTERNALLY_CHECKED
→ CITATION_CHECKED
→ REVIEWED
→ APPROVED
```

事实标签：

```text
[VERIFIED]      已有明确数据、代码或文献支持
[INFERRED]      基于证据的合理推断
[UNVERIFIED]    尚未核验
[CONFLICTING]   与其他材料存在冲突
```

`[UNVERIFIED]` 和 `[CONFLICTING]` 内容不能直接进入最终稿。

## 6. 针对 LIBS 稀土元素识别的强制检查点

### 6.1 任务边界

必须区分：

- 元素存在性识别；
- 多元素分类；
- 定性分析；
- 定量分析；
- 单元素检测；
- 多元素同时识别。

### 6.2 数据划分

优先按样品或批次划分，而不是直接按单条光谱随机划分。需要检查：

- 同一样品的重复光谱是否跨越训练集和测试集；
- 同一制样批次是否同时进入训练集和测试集；
- 预处理参数是否使用了测试集统计量；
- 跨样品、跨批次或外部测试是否必要。

### 6.3 物理解释

以下三者不能混同：

```text
模型相关性分析
≠ 谱线物理归属
≠ 因果机制证明
```

任何物理机制解释都应结合谱线数据库、标准样品、峰位匹配或独立实验。

### 6.4 结论范围

除非有跨仪器、跨样品或外部验证，否则建议使用限定表达：

> 在本研究样品、仪器配置和测试条件下……

不应无证据使用“普适”“实时”“在线”“无损”“可替代标准方法”等强应用表述。

## 7. 最终质量检查清单

### 文献

- [ ] 文献元数据已核验。
- [ ] 关键引用可以定位到页码、图或表。
- [ ] 引用强度没有超过原文证据。
- [ ] 识别、分类和定量研究没有混淆。
- [ ] 重复文献已处理。

### 数据和实验

- [ ] 原始数据未被覆盖。
- [ ] 数据字典和单位完整。
- [ ] 数据划分没有明显样品级泄漏。
- [ ] 预处理参数可追溯。
- [ ] 正式运行有唯一 `run_id`。
- [ ] 失败实验和异常运行有记录。

### 代码和复现

- [ ] Python/MATLAB 入口和版本明确。
- [ ] 没有依赖工作区残留变量或绝对路径。
- [ ] 随机种子和关键配置已记录。
- [ ] 主要图表和表格可以重新生成。
- [ ] 关键结果经过至少一次独立核验。

### 论文

- [ ] 研究问题、方法、结果和结论闭环。
- [ ] 每个核心结论都有证据链。
- [ ] 摘要、正文、图表中的数字一致。
- [ ] 术语、符号、单位和缩写一致。
- [ ] 讨论没有超出实验支持范围。
- [ ] 局限性已经明确。
- [ ] 主要审稿意见都有处理记录。
